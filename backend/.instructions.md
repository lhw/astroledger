# Backend Instructions

## Stack

- Go 1.26
- chi (`github.com/go-chi/chi/v5`) for HTTP routing and middleware
- SQLite via `modernc.org/sqlite` (pure Go, no CGo)
- sqlc (`github.com/sqlc-dev/sqlc`) for type-safe SQL codegen
- goose (`github.com/pressly/goose/v3`) for database migrations
- coreos/go-oidc (`github.com/coreos/go-oidc/v3`) + `golang.org/x/oauth2` for SCID OIDC auth
- golang-jwt/jwt (`github.com/golang-jwt/jwt/v5`) for session JWTs
- go-chi/httprate for rate limiting
- slog (stdlib `log/slog`) for structured logging
- testify (`github.com/stretchr/testify`) for test assertions
- golangci-lint for linting
- Task (taskfile.dev) for build/test/lint/migrate commands

## Running

```sh
cd backend
task dev        # run server with live reload
task migrate    # run goose migrations
task test       # run tests
task lint       # run golangci-lint
```

## Conventions

- Handlers are thin — parse request, validate input, call service, write JSON response. No business logic in handlers.
- Services contain business logic. They accept `context.Context` as first param and return `(result, error)`. No HTTP types in services.
- Always handle errors explicitly. Never discard with `_`. Wrap: `fmt.Errorf("doing X: %w", err)`.
- Use `defer` for cleanup: `defer rows.Close()`, `defer resp.Body.Close()`, `defer tx.Rollback()`.
- Use `database/sql` transactions for multi-row mutations. Pattern: `tx, err := db.BeginTx(ctx, nil)` → `defer tx.Rollback()` → do work → `return tx.Commit()`.
- Use `log/slog` for structured logging. Never log tokens, secrets, or sensitive user data.
- Currency (bUEC) is integer arithmetic. Never use float for balances or costs.
- HTTP status codes: 200, 201, 400, 401, 403, 404, 422, 429, 500.
- JSON: `{"data": ...}` for success, `{"error": {"code": "...", "message": "..."}}` for errors.
- SQL queries live in `queries/*.sql`. Run `task sqlc` after changing them. Never edit `internal/db/` by hand.
- Write table-driven tests with testify assertions.
- Rate-limit `/auth/callback`, `POST /api/markets`, and trading endpoints.

## Auth (SCID / OIDC)

- All auth is via SCID (scid.my) — OIDC confidential client with Authorization Code Flow + PKCE.
- No local passwords. No registration endpoint.
- After successful OIDC callback: validate state, exchange code for tokens, validate id_token signature via JWKS, validate claims (iss, aud, exp), upsert local user from `sub` claim, issue session cookie.
- Session cookie: httpOnly, Secure, SameSite=Lax. Contains a signed JWT with user ID and expiry.
- `SCID_CLIENT_ID` and `SCID_CLIENT_SECRET` from environment variables only.
- RSI OIDC claims stored on login: `rsi_handle`, `rsi_verified`, `rsi_enlisted`, `rsi_citizen_record`, `picture` (avatar_url).

## AMM (LMSR)

The market maker uses the Logarithmic Market Scoring Rule:

- Cost: `C(q) = b * ln(exp(q_yes/b) + exp(q_no/b))`
- Price of YES: `p_yes = exp(q_yes/b) / (exp(q_yes/b) + exp(q_no/b))`
- Use the log-sum-exp trick to avoid float64 overflow: `ln(exp(a) + exp(b)) = max(a,b) + ln(1 + exp(-|a-b|))`
- Cost to buy Δ YES shares: `C(q_yes + Δ, q_no) - C(q_yes, q_no)`
- Liquidity parameter `b` is configurable per market (default 100).
- Multi-choice markets use independent per-outcome pools.

## Auto-filter

Rules stored in DB (`autofilter` table), checked on market submission:

- `keyword`: reject if title/description contains a keyword
- `regex`: reject if title/description matches a pattern
- `rate_limit`: reject if user submitted more than N markets in last 24h
- `min_length`: reject if description is under minimum character count
- `duplicate`: flag if title similarity to existing markets exceeds threshold
