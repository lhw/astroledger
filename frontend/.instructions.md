# Frontend Instructions

## Stack

- SvelteKit with TypeScript
- Skeleton UI component library
- Vite (built into SvelteKit)
- Chart.js or Layerchart for price history graphs
- date-fns for date handling
- ESLint + Prettier for formatting

## Structure

```
frontend/
├── package.json
├── svelte.config.js
├── src/
│   ├── routes/               # SvelteKit file-based routing
│   │   ├── +page.svelte      # Home: market list
│   │   ├── +layout.svelte    # Global layout, nav bar
│   │   ├── market/
│   │   │   ├── [id]/+page.svelte    # Market detail + trading
│   │   │   └── submit/+page.svelte  # Submit new market
│   │   ├── leaderboard/+page.svelte
│   │   ├── profile/+page.svelte
│   │   ├── mod/+page.svelte         # Moderator dashboard
│   │   ├── login/+page.svelte
│   │   └── register/+page.svelte
│   ├── lib/
│   │   ├── api.ts            # Centralized fetch wrapper
│   │   ├── stores/           # Svelte stores (auth state, user data)
│   │   └── components/       # Reusable components
│   └── app.html
└── static/
```

## Conventions

- Use Skeleton UI components (buttons, cards, modals, tables, toasts) instead of custom HTML/CSS.
- All API calls go through `src/lib/api.ts` — never use raw `fetch` in components.
- Store auth tokens in httpOnly cookies (set by the backend). The frontend should not store JWT in localStorage.
- Use TypeScript strictly. Avoid `any`. Define types/interfaces for API responses.
- Use Svelte stores for shared state (current user, auth status, toast notifications).
- Use SvelteKit's `+page.server.ts` or `+page.ts` load functions for server-side data fetching where appropriate.
- Sanitize any user-generated markdown before rendering to prevent XSS.
- Keep components small and focused. Extract reusable pieces into `src/lib/components/`.

## Theming

- Use Skeleton's theming system. Aim for a dark, space-themed look that fits the Star Citizen aesthetic.
- Keep the tone satirical in copy — placeholder text should be funny, not generic lorem ipsum.
