# Backend Instructions

## Stack

- Go 1.22+
- chi (`github.com/go-chi/chi/v5`) for HTTP routing and middleware
- SQLite via `modernc.org/sqlite` (pure Go, no CGo)
- sqlc (`github.com/sqlc-dev/sqlc`) for type-safe SQL codegen
- goose (`github.com/pressly/goose/v3`) for database migrations
- coreos/go-oidc (`github.com/coreos/go-oidc/v3`) + `golang.org/x/oauth2` for SCID OIDC auth
- golang-jwt/jwt (`github.com/golang-jwt/jwt/v5`) for session JWTs
- go-chi/httprate for rate limiting
- slog (stdlib `log/slog`) for structured logging
- testify (`github.com/stretchr/testify`) for test assertions
- golangci-lint for linting
- Task (taskfile.dev) for build/test/lint/migrate commands

## Conventions

- Handlers are thin — parse request, validate input, call service, write JSON response. No business logic in handlers.
- Services contain business logic. They accept `context.Context` as first param and return `(result, error)`. No HTTP types (`http.Request`, `http.ResponseWriter`) in services.
- Always handle errors explicitly. Never discard errors with `_`. Wrap errors with `fmt.Errorf("doing X: %w", err)`.
- Use `defer` for cleanup: `defer rows.Close()`, `defer resp.Body.Close()`, `defer tx.Rollback()`.
- Use `database/sql` transactions for multi-row mutations. Pattern: `tx, err := db.BeginTx(ctx, nil)` → `defer tx.Rollback()` → do work → `return tx.Commit()`.
- Use `log/slog` for structured logging. Never log tokens, secrets, or sensitive user data.
- Use `context.Context` propagation from HTTP handlers through services to database calls.
- Currency (ScollyBucks™) is integer arithmetic. Never use float for balances or costs.
- Use HTTP status codes correctly: 200, 201, 400, 401, 403, 404, 422, 429, 500.
- JSON responses use `{"data": ...}` for success and `{"error": {"code": "...", "message": "..."}}` for errors.
- SQL queries live in `queries/*.sql`. Run `sqlc generate` after changing them. Never edit `internal/db/` by hand.
- Write table-driven tests with testify assertions. Use subtests for related cases.
- Rate-limit `/auth/callback`, `POST /api/markets`, and trading endpoints.

## Auth (SCID / OIDC)

- All auth is via SCID (scid.my) — OIDC confidential client with Authorization Code Flow + PKCE.
- No local passwords. No registration endpoint.
- OIDC flow lives in `internal/service/auth.go` and `internal/handler/auth.go`.
- After successful OIDC callback: validate state, exchange code for tokens (server-side), validate id_token signature via JWKS, validate claims (iss, aud, exp), create/update local user from `sub` claim, issue session cookie.
- Session cookie: httpOnly, Secure, SameSite=Lax. Contains a signed JWT with user ID and expiry.
- `SCID_CLIENT_ID` and `SCID_CLIENT_SECRET` come from environment variables only.
- The SCID OIDC discovery URL is `https://scid.my/.well-known/openid-configuration`.

## AMM (LMSR)

The market maker uses the Logarithmic Market Scoring Rule. Key formulas:

- Cost: `C(q) = b * ln(exp(q_yes/b) + exp(q_no/b))`
- Price of YES: `p_yes = exp(q_yes/b) / (exp(q_yes/b) + exp(q_no/b))`
- Use the log-sum-exp trick to avoid float64 overflow: `ln(exp(a) + exp(b)) = max(a,b) + ln(1 + exp(-|a-b|))`
- Implement in `internal/service/amm.go` with thorough table-driven tests.
- Cost to buy Δ YES shares: `C(q_yes + Δ, q_no) - C(q_yes, q_no)`

Use `math` or `decimal` for precision. The liquidity parameter `b` is configurable per market (default 100).

## Auto-filter

The auto-filter runs on market submission before the mod queue. Rules are stored in the database (`AutoFilterRule` model) and loaded at startup / cached. Rule types:

- `keyword`: reject if title or description contains any keyword from the list
- `regex`: reject if title or description matches a regex pattern
- `rate_limit`: reject if user has submitted more than N markets in 24h
- `min_length`: reject if description is under a minimum character count
- `duplicate`: flag if title similarity to existing markets exceeds threshold
