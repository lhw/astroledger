# Backend Instructions

## Stack

- Python 3.12+, managed with `uv`
- FastAPI for the web framework
- SQLite via SQLModel (SQLAlchemy + Pydantic)
- Alembic for migrations
- JWT auth via python-jose, passwords hashed with bcrypt (passlib)
- APScheduler for scheduled tasks (weekly payouts)
- Ruff for linting/formatting
- Pytest for testing

## Structure

```
backend/
├── pyproject.toml
├── alembic/
├── src/scolymarket/
│   ├── main.py          # FastAPI app, middleware, lifespan
│   ├── config.py        # Pydantic settings
│   ├── database.py      # engine, session dependency
│   ├── models/          # SQLModel table models
│   ├── routers/         # API route handlers (thin)
│   ├── services/        # Business logic
│   └── schemas/         # Request/response models if separate from table models
└── tests/
```

## Conventions

- All route handlers are `async def`.
- Use `Depends()` for DB sessions, current user, and service injection.
- Routers are thin — delegate logic to services.
- Use SQLModel for both table definitions and Pydantic schemas where possible. Create separate response schemas when the table model exposes internal fields.
- Never return password hashes or internal IDs that shouldn't be exposed.
- Use HTTP status codes correctly: 201 for creation, 404 for not found, 403 for forbidden, 422 for validation errors.
- All monetary operations (buying/selling shares, payouts) must be wrapped in a transaction.

## AMM (LMSR)

The market maker uses the Logarithmic Market Scoring Rule. Key formulas:

- Cost: `C(q) = b * ln(exp(q_yes/b) + exp(q_no/b))`
- Price of YES: `p_yes = exp(q_yes/b) / (exp(q_yes/b) + exp(q_no/b))`
- Cost to buy Δ YES shares: `C(q_yes + Δ, q_no) - C(q_yes, q_no)`

Use `math` or `decimal` for precision. The liquidity parameter `b` is configurable per market (default 100).

## Auto-filter

The auto-filter runs on market submission before the mod queue. Rules are stored in the database (`AutoFilterRule` model) and loaded at startup / cached. Rule types:

- `keyword`: reject if title or description contains any keyword from the list
- `regex`: reject if title or description matches a regex pattern
- `rate_limit`: reject if user has submitted more than N markets in 24h
- `min_length`: reject if description is under a minimum character count
- `duplicate`: flag if title similarity to existing markets exceeds threshold
